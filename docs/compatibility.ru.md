# Можно ли заменить herdr на herdr-yazi во всех командах

[English](compatibility.md)

Для запуска приложения, `--remote`, команд `pane`/`agent`/`workspace` и чтения статуса обычно достаточно заменить имя команды. Аргументы передаются без изменений. В версии 0.2.3 команды управления сохраняют сокет и идентификаторы текущей панели, поэтому `--current` работает в контексте вызывающей панели.

Это не полностью независимая установка Herdr. Отличия и исключения:

| Сценарий | Что учитывать |
|---|---|
| Обычный запуск без выбранной сессии | По умолчанию используется `yazi-links`, а не прежняя сессия. Проекты и панели автоматически не переносятся |
| Команда из панели Herdr | `pane`, `agent` и другие команды управления наследуют её сокет, сессию и идентификаторы. Они могут обращаться к обычному серверу, если запущены внутри него |
| `--session NAME`, `session attach NAME` | Сессию выбирает Herdr. Подключение к старому серверу не превращает его в сборку с патчем |
| `herdr-yazi update` | Штатный обновлятор может заменить `.build/bin/herdr` официальным бинарником без патча. Для нашей сборки используй процедуру обновления из `patched-herdr.ru.md`. Команда намеренно не перехватывается |
| `--remote HOST` | На хосте нужны репозиторий по ожидаемому пути, плагин, Python, Yazi и подходящая сборка. Подготовка не устанавливает зависимости и не заменяет работающий сервер |
| `machine add`, сохранённые машины | Это штатный механизм Herdr, он не вызывает наш `prepare.sh`. Нужную удалённую сессию сначала подготовь на хосте; при добавлении укажи её через `--remote-session yazi-links` |
| Конфигурация и плагины | Используются обычные каталоги конфигурации Herdr. Отдельной является сессия, а не весь профиль настроек. `config`, `plugin`, `machine`, `channel` могут менять общие настройки |
| `completion zsh` | Генератор выдаёт дополнение для имени `herdr`. После загрузки обычного completion и `compinit` добавь `compdef _herdr herdr-yazi` |
| Скрипты и интеграции с буквальным `herdr` | Они продолжат вызывать обычный Herdr. Переименование твоей команды в терминале не переписывает внешние скрипты |
| Новые функции апстрима | Обёртка пропустит новые аргументы, но старая закреплённая версия бинарника может их ещё не поддерживать |

Не выполняй `update` ради проверки совместимости: это изменяющая бинарник операция. Исходники обновлятора показывают, что он заменяет текущий исполняемый файл.

Проверки аудита: аргументы и коды завершения, `--current` на реальной панели, чтение справки/версии/конфигурации/skill/API-схемы и генерация completion при одинаковой сессии, настоящий SSH-клик на Mac с `--remote-keybindings server`. Обёртка сохраняет приоритет существующего PATH и добавляет запасные каталоги инструментов в конец. Это набор проверенных сценариев, а не гарантия поведения любого будущего изменения апстрима.

### Управляемый сервер Linux

При установке нового режима правила выше уточняются: `~/.local/bin/herdr`
указывает на вход надстройки и имеет приоритет в zsh, включая SSH. Сохранённые
машины должны заново обнаружить этот путь. `yazi-links` запускается через
пользовательскую службу; `update` и `channel` через эту точку входа запрещены.
Прямой `/usr/bin/herdr` остаётся доступен и обходит эти правила. Подробности:
[управление сервером](server-management.ru.md).
