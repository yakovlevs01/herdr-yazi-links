# Рабочий стол принадлежит клиенту

Сервер Herdr хранит панели и процессы. Его окружение может происходить от старого
SSH-подключения и не описывает компьютер, с которого пользователь работает сейчас.
Патч для Herdr 0.9.4 передаёт графические операции текущему клиенту.

## Что меняется

- Ctrl+G в Yazi использует клиента, приславшего эту клавишу. Локально запускается
  ripdrag с графическим окружением клиента. При удалённом подключении файл
  скачивается по SFTP и передаётся ripdrag на компьютере клиента.
- Enter в Yazi, открытом через файловую ссылку Herdr, отправляет GUI opener тому
  же клиенту. При удалённом открытии скачивается копия файла. Изменения копии
  обратно на сервер не синхронизируются. Терминальные редакторы работают на сервере.
- Вставку картинки обрабатывает клиент и передаёт файл серверу. Это работает
  и с локальным сервером, ранее запущенным через SSH.
- Текст через OSC 52 получает клиент, вводивший в соответствующую панель.
  Если одну панель одновременно смотрят несколько активных клиентов, автоматическая
  запись в буфер отклоняется. В этом случае используй выделение и копирование
  средствами самого клиента. Прямой вызов серверного wl-copy/pbcopy по-прежнему
  обращается к серверу, поэтому редакторы должны использовать терминальный OSC 52.

Контекст операции действует один раз, не более пяти секунд. При конфликте
клиентов, отключении или отсутствии приёмника операция выдаёт ошибку.
Она не переключается на рабочий стол сервера или на старого клиента.

Каждый запуск `herdr-yazi` создаёт собственный идентификатор приёмника и следит
за его жизнью. Сохранённые SSH-машины получают отдельные приёмники этого клиента.
Mac и IW могут подключаться к одной сессии, не перехватывая передачи друг друга.
Общий фоновый сервис приёмников нужен только старым клиентам.

## Обновление

Нужны новый сервер, новый клиент и обновлённый Lua-плагин Yazi на каждой машине.
Сервер можно обновить через live handoff с сохранением панелей и процессов.
Клиент затем запускается снова командой `herdr-yazi`. Открытый Yazi следует
закрыть клавишей q и открыть заново, чтобы он загрузил новый Lua-плагин и opener.
После этого переключение между клиентами не требует новых панелей Yazi.

Запускай Herdr на своём компьютере через `herdr-yazi`, а к другим машинам
подключайся через сохранённую машину или `herdr-yazi --remote HOST`.
Обычный `ssh HOST`, внутри которого запущен Herdr, не даёт ему доступа
к графическому буферу и drag-and-drop внешнего компьютера. В этом режиме
операция не пытается угадать рабочий стол; используй нативный клиент Herdr.
Старые серверы сохраняют прежний режим совместимости, включая его ограничения.

## Устройство и проверки

Клиент регистрирует `client.desktop.register` на своём соединении. Сервер
связывает Ctrl+G и Enter с этим соединением; helper забирает однократный контекст
через `pane.desktop.take`. Передаются только семь графических переменных,
без PATH и без SSH-переменных. Приёмники разделены ключом session@client-id.
Контекст удаляется при отключении, а после handoff клиент регистрируется снова.

`desktop-bin/xdg-open` и `desktop-bin/open` добавляются в PATH только Yazi,
запущенного расширением. Произвольные команды в старых shell-панелях
не меняют окружение. Для обычного shell-запуска Yazi Ctrl+G работает через
обновлённый Lua-плагин, а системное открытие требует этих opener-обёрток.

```sh
python3 -m unittest discover -s tests -v
python3 scripts/desktop-smoke.py --herdr .build/bin/herdr
```

PTY-проверка запускает сервер со старым SSH-окружением, два клиента и одну
панель Yazi. Она проверяет Ctrl+G, Enter, вставку разных PNG и направление OSC 52.
Графические программы и буфер в этой проверке заменены регистраторами:
реальный пользовательский буфер не затрагивается. Передачу между компьютерами
проверяет `scripts/drag-smoke.py`, включая `--saved-machine`.
