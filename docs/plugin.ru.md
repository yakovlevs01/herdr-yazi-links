# Открытие файловых ссылок в Yazi

Community-плагин Herdr открывает файловую гиперссылку в панели Yazi справа. Yazi выделяет нужный файл или открывает каталог. Нажми `q`, чтобы закрыть панель.

[English](plugin.md) · [Обзор репозитория](../README.ru.md)

## Установка

Нужны Herdr с совместимым API плагинов, Python 3 и Yazi. Python и Yazi должны быть доступны в PATH сервера Herdr.

```sh
herdr plugin install yakovlevs01/herdr-yazi-links
```

Для этого режима не нужны отдельная сборка Herdr или обёртка запуска. Мы проверили его на Linux с обычным Herdr 0.9.0. Новые версии нужно проверять командами ниже; macOS и удалённые сессии пока не проверяли.

Для разработки клонируй репозиторий и подключи его:

```sh
herdr plugin link /абсолютный/путь/к/herdr-yazi-links
```

## Что должно выводить приложение

Кликабельный элемент должен быть терминальной гиперссылкой OSC 8 с абсолютным файловым URI:

```text
file:///home/user/project/README.md
```

Формат протокола: `ESC ] 8 ; ; URI ST LABEL ESC ] 8 ; ; ST`. Здесь `ESC` означает байт `0x1b`, а `ST` состоит из `ESC` и обратной косой черты. Пробелы, `#`, `%` и другие специальные символы URI нужно кодировать через проценты. Файл или каталог должен существовать на машине сервера Herdr. Допускается пустое имя хоста, `localhost` или имя этого сервера.

Агент может написать такой Markdown:

```markdown
[README.md](file:///home/user/project/README.md)
```

Это работает, только если приложение агента преобразует ссылку в OSC 8 и сохраняет адрес `file://`. Самого текста Markdown недостаточно. Ни фрагмент кода `README.md`, ни вывод URI обычным текстом не гарантируют появления гиперссылки. Подпись может быть относительным именем файла, но адрес ссылки должен содержать абсолютный путь.

## Проверка без агента

Клонируй репозиторий, перейди в него в панели Herdr и запусти:

```sh
python3 scripts/demo.py
```

Нажми Ctrl и кликни по файловой гиперссылке. Рядом с исходной панелью должен открыться Yazi. Демонстрация также печатает обычные пути для сравнения; в стандартном Herdr этот плагин их не распознаёт.

Автоматические проверки из репозитория:

```sh
python3 -m unittest discover -s tests -v
python3 scripts/smoke.py --herdr /usr/bin/herdr
```

Smoke-тест на Linux создаёт отдельную сессию и конфигурацию, отправляет настоящий Ctrl+клик через PTY и проверяет выделение файла в настоящем Yazi. Он также проверяет, что обычные пути без патча не вызывают плагин. Рабочие сессии тест не затрагивает. GitHub Actions запускает проверку на Herdr 0.9.0 и последнем релизе при изменениях и раз в неделю.

## Диагностика и ограничения

Если клик ничего не делает, сначала запусти демонстрацию. Если она работает, проверь, выдаёт ли приложение файловые гиперссылки OSC 8. Если клик дошёл до плагина, но Yazi не открылся, посмотри журнал:

```sh
herdr plugin log list --plugin local.yazi-links
```

Yazi запускается на сервере Herdr, которому принадлежит панель. Для удалённого сервера там потребуются плагин, Python и Yazi; этот режим пока не проверяли. Запуск удалённого Yazi не переносит файл на локальный компьютер.

Плагин проверяет путь и передаёт его аргументом, без выполнения текста как shell-команды. Обычные пути в сообщениях требуют [дополнительного патча Herdr](patched-herdr.ru.md).

## Публикация плагина

Опубликуй этот репозиторий на GitHub с открытым доступом, сохрани `herdr-plugin.toml` в основной ветке и добавь тему `herdr-plugin`. Манифест в корне устанавливает только плагин. Для файловых гиперссылок пользователю не нужны патч и зависимости сборки Herdr.

При каждом выпуске обновляй версию в манифесте и changelog, затем создавай тег `vMAJOR.MINOR.PATCH`. Каталог community-плагинов автоматически индексирует подходящие репозитории и исключает форки. Наличие в каталоге не означает официального одобрения. См. [документацию каталога](https://herdr.dev/docs/marketplace/).
