# Yazi через Herdr --remote

[English](remote.md) · [Плагин без патча](plugin.ru.md)

Локальный клиент передаёт Ctrl+клик серверу Herdr. Сервер определяет путь и запускает свой плагин, который открывает Yazi на этом же хосте. Относительные пути считаются от рабочей папки удалённой панели. Файлы не копируются на локальный компьютер.

## Установка

На каждом удалённом хосте нужны Herdr, Yazi и Python 3. Для обычных текстовых путей нужен также бинарник Herdr с патчем, собранный для ОС и архитектуры этого хоста. Linux x86_64 бинарник не подходит Mac ARM64.

Для одного плагина выполни на сервере:

```sh
herdr plugin install yakovlevs01/herdr-yazi-links
```

После этого файловые OSC 8 гиперссылки должны открываться при обычном `herdr --remote HOST`. Для текстовых путей размести этот репозиторий на сервере в `~/pets/herdr-yazi-links`, а собранный бинарник в `.build/bin/herdr` внутри него. С локального компьютера:

```sh
herdr-yazi --remote HOST
```

Команда вызывает удалённый `herdr-yazi --prepare`, регистрирует плагин и при необходимости запускает отдельный сервер сессии `yazi-links`. Затем локальный клиент подключается к ней через `--remote`. Скрипт не копирует зависимости или бинарник и не заменяет работающий сервер. После обновления бинарника уже работающая сессия продолжает использовать старый процесс до явного перезапуска.

Команда добавляет `~/.local/bin`, `/opt/homebrew/bin` и `/usr/local/bin` в PATH запускаемого сервера, поскольку обычная SSH-команда может не получить PATH интерактивного shell. Для установки Yazi в другом каталоге настрой PATH сервера.

## Проверка без агента

Из локального Linux checkout, с рабочим SSH-доступом и уже установленной удалённой сборкой:

```sh
python3 scripts/smoke.py --herdr /usr/bin/herdr \
  --remote HOST --remote-root /absolute/path/to/herdr-yazi-links \
  --expect-paths
```

Тест создаёт временный файл и отдельную сессию `smoke-<случайный ID>` на удалённом хосте, запускает настоящий локальный клиент `herdr --remote`, отправляет Ctrl+клики и проверяет выбранный файл в удалённом Yazi. Он проверяет OSC 8, относительный и абсолютный пути, а также несуществующий файл. После проверки останавливает только свою тестовую сессию. Регистрация установленного плагина сохраняется. Тест требует SSH forwarding Unix-сокетов.

GitHub Actions проверяет локальный режим. Remote-тест запускается явно на доступном SSH-хосте; публичный CI не получает доступ к личным компьютерам.

## Python

Python нужен обработчику плагина для декодирования URI, проверки файла, разбора контекста JSON и запроса `plugin.pane.open` через Unix-сокет. Сторонних Python-пакетов нет. Для запуска плагина достаточно Python 3.9+, для скриптов сборки требуется Python 3.11+ с `tomllib`.

Python можно заменить нативным обработчиком. Тогда для установки потребуются отдельные сборки этого обработчика под Linux и macOS, x86_64 и ARM64. Текущий релиз сохраняет реализацию на Python.

Запуск `ssh HOST` внутри обычной панели не меняет принадлежность панели серверу Herdr. Для этого случая автоматическое распознавание удалённого хоста не реализовано.

Проверили обычный локальный Herdr 0.9.0 на Linux с удалёнными серверами Linux x86_64 и macOS ARM64, собранными с патчем. См. [результаты](../VALIDATION.md).
