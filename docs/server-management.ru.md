# Локальный сервер и подключение с Mac

На Linux/zsh `./install.sh --managed-server` ставит `herdr-yazi-server.service` и точку входа
`~/.local/bin/herdr`. `herdr-yazi` и SSH-подключение к `yazi-links` запускают
сервер через эту службу. Служба использует закреплённый `.build/bin/herdr`.
Системный `/usr/bin/herdr` не изменяется. На macOS запуск остаётся прежним.

Установка: `./install.sh --managed-server`. Повторные установки сохраняют включённый режим. Для уже установленного проекта без скачивания
бинарников: `python3 scripts/install-server.py`. Установщик ничего не останавливает.
Автоматическая настройка SSH PATH сейчас поддерживает zsh: управляемая строка
в `~/.zshenv` делает точку входа доступной в неинтерактивном SSH.

Служба стартует по запросу, не при загрузке ПК. Ей нужен работающий локальный
рабочий стол и его окружение в `systemctl --user show-environment`.
SSH-окружение в службу не передаётся. Локальный launcher может импортировать
графические переменные своего рабочего стола. При отсутствии графического
сокета запуск завершается ошибкой; запасного запуска сервера из SSH нет.
В Hyprland этой машины окружение уже импортируется в пользовательский systemd.
Если compositor сменится, это условие нужно проверить заново.

## Однократный переход существующей сессии

Работающий старый сервер автоматически не заменяется: launcher присоединяется
к нему с предупреждением. До перехода проблема буфера в старых агентах остаётся.
Сохрани работу: остановка сервера завершит процессы всех панелей этой сессии.
Из отдельного локального терминала, **вне Herdr**, выполни:

```sh
/usr/bin/herdr --session yazi-links server stop
python3 ~/pets/herdr-yazi-links/scripts/server-manager.py ensure
herdr-yazi
```

Не делай это из активной панели агента. Восстановление формы сессии не гарантирует
сохранения состояния каждого процесса. Диалоги агентов продолжай их командами resume.

Перезапусти клиент Herdr на Mac, чтобы он заново нашёл `~/.local/bin/herdr`,
а не использовал ранее найденный `/usr/bin/herdr`. Для сохранённой машины нужна
сессия `yazi-links`. Проверка на Mac: `ssh HOST 'command -v herdr'`.
Ожидается `/home/arasanya/.local/bin/herdr` для этого ПК.

## Проверки и обновления

```sh
systemctl --user status herdr-yazi-server.service
journalctl --user -u herdr-yazi-server.service
python3 -m unittest discover -s tests -v
python3 scripts/smoke-server.py
./install.sh --check
```

Smoke создаёт отдельную краткоживущую службу и конфигурацию. Проверяет запуск
из локального и SSH-подобного окружений, SID, отсутствие SSH-переменных и
готовность настоящего закреплённого сервера. Это не заменяет проверку вставки
скриншота в агент и реального клиента Mac.

Установщик, служба, launcher и тесты версионируются вместе. Обновляй закреплённую
сборку по `docs/patched-herdr.ru.md`. `herdr update` и `herdr channel` через
управляемую точку входа заблокированы, чтобы не перезаписать сборку обновлятором.
Установщик не перезапускает сервер после обновления. Прямой запуск
`.build/bin/herdr` или `/usr/bin/herdr` обходит управление службой; используй
`herdr-yazi` для запуска приложения. Прямые API-команды внутри существующей
панели остаются доступны. Другие именованные сессии не переводятся в systemd.

Служба пользователя не является logind-графической сессией. Это даёт серверу
стабильное окружение и независимость от SSH, но не обещает графические функции
до входа в рабочий стол или автоматическое обновление окружения уже работающих
процессов после перезапуска compositor.

Откат настройки: после сохранения работы останови службу, убери ссылку
`~/.local/bin/herdr`, восстанови её резервную копию при наличии, удали добавленный
блок из `~/.zshenv`, `.build/server-management.json` и файл службы, затем выполни
`systemctl --user daemon-reload`. Системный Herdr при установке не изменяется.
