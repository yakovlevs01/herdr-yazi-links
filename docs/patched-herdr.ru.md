# Дополнительный патч Herdr для путей обычным текстом

Патч позволяет нажать Ctrl и кликнуть по существующему пути в обычном терминальном тексте. Например, агент может написать `README.md` или `src/main.rs` без гиперссылки. Плагин откроет Yazi в панели справа.

[English](patched-herdr.md) · [Плагин без патча](plugin.ru.md)

## Сборка и запуск

Установи версии инструментов из [patches/upstream.toml](../patches/upstream.toml), а также Python 3.11+, Git и Bash 4+. Сейчас закреплены Rust 1.98.1 и Zig 0.16.0. Для сборки и автоматических проверок нужен Linux с установленным Yazi в PATH, rustup, C/C++ компилятор и pkg-config. Из репозитория:

```sh
./build.sh
# Если Zig отсутствует в PATH:
# ZIG=/абсолютный/путь/к/zig ./build.sh
./scripts/prepare.sh
./herdr-yazi
```

Подготовка подключает плагин; команда запуска открывает отдельную сессию `yazi-links` через `.build/bin/herdr`. Она не заменяет `/usr/bin/herdr` и не перезапускает существующие сессии. Чтобы добавить её в PATH:

```sh
mkdir -p ~/.local/bin
ln -s "$PWD/herdr-yazi" ~/.local/bin/herdr-yazi
```

Внутри этой сессии запусти `python3 scripts/demo.py`. Проверь Ctrl+клик по гиперссылке и обычным путям. Автоматическая проверка из репозитория:

```sh
python3 scripts/smoke.py --herdr .build/bin/herdr --expect-paths --expect-home-paths
```

## Как работает распознавание

Сначала Herdr ищет готовую терминальную гиперссылку. Если её нет, патч использует сопоставление ячеек терминала с текстом и находит текст под Ctrl+кликом, включая переносы длинных строк и Unicode. Он выделяет возможный путь, убирает обрамляющую пунктуацию и проверяет, существует ли такой обычный файл или каталог.

Абсолютный путь задаёт расположение самостоятельно. Относительный путь, включая одно имя файла, отсчитывается от рабочей папки процесса исходной панели. Поэтому слово `tests` может открыть одноимённый каталог. Если агент имел в виду другой проект, проверка существования не обнаружит ошибку.

Префикс `~/` разворачивается в домашнюю папку пользователя на сервере Herdr. Например, `~/pets/project/README.md` работает независимо от рабочей папки панели. `~user/` не разворачивается.

Пути в кавычках, содержащие `/`, могут включать пробелы. Пробелы без кавычек и суффиксы `:строка:колонка` не поддерживаются. Плагин передаёт путь аргументом и не выполняет текст под кликом. Готовые терминальные гиперссылки имеют приоритет; HTTP(S) открывается привычным способом.

## Что произойдёт при обновлении Herdr

| Действие | Результат |
|---|---|
| Обновить системный Herdr | Изменится `/usr/bin/herdr`; `.build/bin/herdr` останется прежним |
| После этого запустить `herdr-yazi` | Используются прежний собственный бинарник и сессия `yazi-links` |
| Запустить `build.sh` без изменения ревизии | Пересоберётся закреплённая ревизия, не свежий апстрим |
| Собрать новую закреплённую ревизию | После успешных проверок сборки появится новый собственный бинарник |
| Оставить прежний сервер работающим | Он продолжит работать со старым исполняемым файлом до явного перезапуска |

Чтобы продолжать пользоваться прежней сборкой после системного обновления, дополнительных действий не нужно. Чтобы получить в ней исправления или функции апстрима, нужно обновить ревизию и патч, проверить, пересобрать, затем перезапустить свою сессию в удобный момент. Скрипты не останавливают рабочий сервер автоматически.

## Проверка новой ревизии апстрима

Укажи полный хеш коммита, а не имя движущейся ветки:

```sh
python3 scripts/check-upstream.py --revision <полный-хеш-коммита>
```

Команда проверяет кандидата в отдельной папке сборки, исключённой из Git. Она проверяет применение патча, запускает тесты, собирает Herdr и выполняет smoke-тест с распознаванием путей. Кандидат сохраняется в `.build/candidates/<хеш>/bin/herdr`; рабочий `.build/bin/herdr` и закреплённая ревизия не меняются. Если апстрим требует новые инструменты, передай `--rust <версия>` и `--zig-version <версия>`; путь к Zig можно задать переменной `ZIG`. При ошибке нужно изучить изменение в апстриме до обновления. Успех подтверждает проверенные сценарии, но не гарантирует совместимость со всеми терминалами и будущими версиями.

Для выпуска с новой ревизией:

1. Изучи изменения апстрима и требования к инструментам сборки.
2. Обнови `patches/upstream.toml` и при необходимости адаптируй `patches/herdr-path-click.patch`. Сохрани их одним коммитом.
3. Запусти проверку кандидата, тесты плагина и ручную демонстрацию с настоящим Yazi.
4. Пересобери через `./build.sh` и запусти smoke-тест сборки с патчем.
5. Сохрани работу в старой сессии `yazi-links`, затем явно заверши её средствами управления сессиями Herdr и снова запусти `herdr-yazi`. Одного закрытия клиента может быть недостаточно, сервер может продолжить работу.

Для каждой ревизии используется отдельная папка `.build/source-<хеш>`. Скрипт откажется использовать исходники с неожиданной ревизией. Рабочий бинарник заменяется атомарно только после успешных тестов и проверки кликов. Не применяй непроверенный патч с приблизительным совпадением и не заменяй рабочую сборку после неудачной проверки.

## Что хранить в репозитории

Плагин, патч, закреплённую ревизию, тесты и скрипты сборки версионируем вместе. Исходники Herdr, кэши и бинарники храним в исключённой из Git папке `.build/`. Плагин для обычного Herdr остаётся полезным и тогда, когда дополнительный патч требует обновления.

Плагин использует сокет сервера Herdr, которому принадлежит панель, поэтому Yazi будет запускаться там. Команда запуска не устанавливает плагин и патч на удалённый хост. Ручное вложенное подключение по SSH не распознаётся.

Подробнее об установке на SSH-хостах и проверке без агента: [удалённая работа](remote.ru.md).
